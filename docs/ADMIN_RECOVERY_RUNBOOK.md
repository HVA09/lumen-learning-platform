# دليل استعادة صلاحية المدير — Lumen

**الغرض:** استعادة وصول الإدارة بطريقة مضبوطة إذا لم يعد في النظام أي حساب مدير نشط. هذا الدليل لا يجيز تعديل قاعدة البيانات يدوياً أو تشغيل الأمر على حساب/بيئة غير معتمدة.

## الضمان الوقائي

تحتفظ المنصة بمدير نشط واحد على الأقل:
- لا يستطيع آخر مدير نشط حذف حسابه من صفحة الملف الشخصي.
- تغييرات دور المدير أو تعطيله أو حذفه تمر عبر قفل مشترك لمجموعة المديرين النشطين.
- أداة bootstrap تستخدم القفل نفسه، ولا تعمل إذا كان هناك مدير نشط.
- تبقى الحسابات الإدارية غير النشطة محفوظة؛ وجودها لا يمنع استعادة مدير نشط جديد عند غياب جميع المديرين النشطين.

## شروط الاستعادة

1. تأكد عبر مالك النظام من أن فقدان صلاحية الإدارة حقيقي، وليس مشكلة جلسة أو اتصال.
2. اختر حساباً قائماً وموثوقاً، حالته `is_active=True` وبريده الإلكتروني مؤكد.
3. يجب أن تكون بيئة التشغيل متصلة بقاعدة PostgreSQL؛ أداة bootstrap ترفض أي dialect آخر.
4. يجب أن يتم التنفيذ من طرفية تفاعلية داخل بيئة الخادم المصرح بها. لا تنسخ كلمات مرور قاعدة البيانات أو مفاتيحها إلى المحادثات أو سجلات التذاكر.

## الإجراء التشغيلي

من مجلد backend وفي البيئة الافتراضية المعتمدة:

```bash
python -m app.ops.promote_initial_admin --email "account@example.com"
```

ستعرض الأداة البيئة واسم المضيف والمنفذ واسم قاعدة البيانات دون بيانات اعتماد، ثم تطلب كتابة عبارة تأكيد حرفية تتضمن البريد والبيئة والهدف. لا تتابع عند أي اختلاف أو شك في قاعدة الهدف. لا تنفذ الأمر الآن لمجرد اختبار الدليل.

تقوم الأداة بالتحقق من:
- وجود الحساب والبريد المؤكد.
- أن الحساب نشط.
- عدم وجود أي مدير نشط حالياً.
- امتلاك معاملة PostgreSQL لقفل مجموعة المديرين قبل الترقية.

تسجل الأداة حدث تدقيق `first_admin_bootstrap` ضمن المعاملة نفسها. أي فشل أو إلغاء يجب ألا ينتج عنه تغيير جزئي.

## التحقق بعد الاستعادة

1. سجّل الدخول بالحساب الذي تمت ترقيته.
2. تحقق من الوصول إلى مسار إداري مصرح مثل `/admin/stats`.
3. راجع سجل التدقيق للتأكد من وجود `first_admin_bootstrap`.
4. أنشئ حساب مدير احتياطياً ثانياً وفق سياسة المؤسسة، بعد التحقق من هوية صاحبه.
5. وثّق من نفذ العملية والبيئة والوقت ونتيجة التحقق، دون حفظ أسرار أو بيانات اعتماد.

## حدود السلامة

- لا تستخدم SQL يدوياً لتغيير `role` أو `is_active`.
- لا تشغّل bootstrap على الإنتاج دون تفويض مالك النظام وإجراء تغيير موثق.
- لا تعتبر نجاح الأداة بديلاً عن اختبار الدخول والتحقق من الصلاحيات.
- لا تجرِ أي migration أو حذف مستخدمين أو تعديل جلسات ضمن إجراء الاستعادة.
- إذا لم تكن قاعدة التشغيل PostgreSQL، أوقف العملية واطلب مسار استعادة معتمداً لذلك النوع من قواعد البيانات بدلاً من تجاوز حماية الأداة.
