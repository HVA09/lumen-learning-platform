# سجل حوكمة المشروع وخطة الاستمرارية — Lumen

**آخر تحديث:** 16 نوفمبر 2026
**المستودع:** `HVA09/lumen-learning-platform`  
**الفرع الأساسي:** `main`  
**آخر رأس تم التحقق منه عند إعداد السجل:** `5a065c00ff739c21cad06d551c7e3aa51a3d604b`  
**حالة حوكمة الفرع:** `main` محمي.  
**حدود هذا السجل:** يخص منصة Lumen التعليمية وحدها، ولا ينقل خطط AI Chat App أو ERP إلى هذا المستودع.

> هذا ملخص الحوكمة ونقطة الاستئناف. استخدم ميثاق المشروع وسجل الاستمرارية وخريطة المعمارية وطلبات الدمج بوصفها مراجع تفصيلية، وأعد فحص GitHub قبل كل تغيير.

## 1. دور Lumen داخل المنظومة الأوسع

Lumen منصة تعليمية مستقلة بالعربية والإنجليزية. تركز على تجربة التعلم والمحتوى والتقييم والتقدم والصفوف والواجبات والمراجعة والمختبرات التعليمية.

- التعليم هو الوظيفة الأساسية لهذا المنتج؛ أما المنظومة العامة الأكبر فتسمح بوجود أهداف غير تعليمية في منتجات أخرى.
- تبقى هوية المستخدمين التعليمية، والسجلات الدراسية، والتقييمات، وقاعدة البيانات، والنشر مستقلة عن AI Chat App وERP.
- يمكن لـ Lumen استهلاك AI Core مستقبلاً عبر API، مع صلاحيات وموافقة واضحة، ودون مشاركة بيانات المتعلم افتراضياً.
- لا يعتمد تسجيل الدخول أو الوصول إلى الدروس والاختبارات على توفر AI Core.

## 2. المراجع التنفيذية

1. `docs/PROJECT_CHARTER.md` — أهداف المشروع وقيوده ومبادئه.
2. `docs/PROJECT_STATUS.md` و`docs/CONTINUITY.md` — الحالة التشغيلية ونقطة الاستئناف؛ يجب تحديث أي ملخص تاريخي بعد التحقق من main.
3. `docs/ARCHITECTURE_PLAN.md` وملفات حدود المجالات والقرارات — ملكية المجالات واتجاهات الاعتماديات.
4. طلب الدمج #6 — وثائق خارطة الطريق وخط الأساس المقترحة؛ ما زال مسودة وفق آخر تحقق هنا، فلا تفترض أن الملفات الواردة فيه جزء من main.
5. هذا السجل — قواعد الفصل والتكامل والأولوية الحالية.

- رأس `main`: `5a065c00ff739c21cad06d551c7e3aa51a3d604b`، ويتضمن ميثاق الجودة الهندسية المدمج عبر PR #153.
- PR #154 هو إعادة تأسيس LTI 1.3 / AGS 2.0 على main الحالي. ما زال مفتوحاً وDraft وغير مدمج؛ HEAD هو `6c93b49c976245b778800ed63046a2aef321fbb9`، بواقع 46 commits ahead و0 behind و31 ملفاً متغيراً عند آخر فحص.
- فحوص CI على HEAD نفسه اكتملت 4/4 بنجاح: Backend، Frontend/production build، Browser E2E، وفحص الأسرار الكامل. مجموعة Backend سجلت 521 اختباراً ناجحاً و12 تحذيراً و90% تغطية، وRuff report-only صفر تشخيصات.
- نجاح CI لا يثبت التكامل مع LMS فعلي. اختبارات Moodle Sandbox وCanvas Sandbox لم تُنفذ بعد لغياب بيانات اعتماد وبيئات Sandbox وبيئة staging عامة متكاملة.
- متبقيات LTI المعروفة: التحقق من at-least-once وعدم افتراض exactly-once، clock skew بين العمال، سياسة الاحتفاظ/الحذف أو تشفير `lti_subject` الخام، وشرط same-origin بين lineitem URL وOAuth token endpoint على كل منصة.
- طلبات #16–#23 القديمة ما زالت طلبات متسلسلة/تاريخية مفتوحة؛ لا تُدمج منفردة ولا تُعامل كخطة بديلة عن PR #154 المعاد تأسيسه.
- لا يوجد في هذا التحقق إثبات لنشر LTI في الإنتاج أو لقبول Moodle/Canvas.

## 4. الأولوية التنفيذية الحالية

1. إبقاء main مستقراً وعدم دمج PR #154 أو تحويله إلى Ready for review قبل إغلاق بوابات القبول الخارجية والخصوصية والتشغيل.
2. تنفيذ Moodle Sandbox ثم Canvas Sandbox كلٌ على حدة، وتوثيق التسجيل وOIDC launch وResource Link mapping وOAuth وGradebook passback وre-grade والمهل وإعادة المحاولة والتكرار والحالات السلبية.
3. حسم سياسة retention/deletion للمعرّف الخارجي `lti_subject`، وتقييم التشفير عند التخزين، وتوثيق من يستطيع الوصول إليه.
4. اختبار clock skew / NTP أو اعتماد وقت موحد موثق للـleases والـretry scheduling في سيناريو العمال المتعددين.
5. إثبات same-origin constraints مع Moodle وCanvas، ثم إعادة تشغيل الاختبارات المطلوبة على HEAD حديث قبل المراجعة والدمج.
6. الحفاظ على Lumen منتجاً تعليمياً مستقلاً؛ أي استهلاك مستقبلي لـAI Core يمر عبر backend وصلاحيات محددة ولا يمنح النواة سلطة تغيير الدرجات أو سجلات التعلم.

## 5. سياسة التطوير والدمج

- كل تغيير وظيفي في فرع وPR مستقل قدر الإمكان.
- الحفاظ على React/Vite وFastAPI/Python وPostgreSQL الحالية ما لم تكشف القياسات أو المخاطر سبباً واضحاً للتغيير.
- لا اعتماد على خدمة مدفوعة أو بطاقة أو مورد إضافي في الخطة الأساسية.
- لا استخدام لبيانات طلاب حقيقية في الاختبارات أو المستودع العام.
- يجب اجتياز اختبارات backend وfrontend والبناء وBrowser E2E وفحص الأسرار؛ وتُضاف اختبارات migration/backup عند تأثير التغيير فيها.
- لا تُعتبر نسبة التغطية وحدها دليلاً على أمان تدفق LTI أو جاهزية الإنتاج.
- توثيق كل مرحلة مع SHA وPR ونتائج الاختبارات الفعلية وما تبقى.

## 6. حدود التكامل مع AI Core

عند توفر AI Core مستقل:

- يُستخدم للتوليد والمساعدة التعليمية والشرح والتغذية الراجعة عند تمكين ذلك.
- يبقى التحكم في سياسات التقييم والدرجات وقرارات إتمام التعلم داخل Lumen؛ لا تمنح النواة صلاحية مباشرة لتغيير الدرجات أو سجلات المستخدمين.
- تمر طلبات AI عبر backend موثوق مع سياسات بيانات المتعلم ومراجعة المحتوى وتسجيل التدقيق عند الحاجة.
- تعطل AI Core لا يمنع التصفح أو الدروس أو الاختبارات أو حفظ التقدم الأساسي.

## 7. ما لا يدخل في هذا المستودع

- AI Chat App كمنتج محادثة عام.
- ERP Global Pro والمعاملات المالية وبيانات الشركات.
- كود AI Core أو منصة المعمارية العامة.
- تُشارك العقود والواجهات فقط، ولا تُدمج قواعد البيانات أو المستودعات.

## 8. قاعدة تحديث هذا السجل

تُحدّث الحالة بعد كل مرحلة من أدلة GitHub وCI وSandbox الفعلية. يجب فصل الحالة المؤكدة عن العمل المخطط، وذكر ما لم يُختبر. عند تحديث `PROJECT_STATUS.md` أو `CONTINUITY.md` تتم مواءمة هذا الملخص معها في PR توثيقي منفصل.

**القرار المعماري:** Lumen يحتفظ بخطته ومنتجه التعليميين؛ الخطة العامة للمنظومة تضبط التكامل الاختياري فقط ولا تستبدل خارطة Lumen.
