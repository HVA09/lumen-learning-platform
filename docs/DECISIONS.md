# سجل قرارات مشروع Lumen

آخر تحديث: 2026-11-02

يسجل هذا الملف القرارات التي اتُّخذت، والتوصيات الهندسية التي اعتُمدت في مسار العمل، وأسبابها وآثارها. لا يعني إدراج توصية أن المستخدم وافق عليها؛ تُذكر جهة القرار وحالته صراحةً.

## طريقة قراءة السجل

- **معتمد — تفضيل المستخدم:** طلب المستخدم القرار بوضوح.
- **معتمد تشغيليًا — توصية هندسية:** اختيار هندسي اتُّبع لتنظيم العمل أو تقليل المخاطر، ويمكن مراجعته إذا ظهرت أدلة أفضل.
- **معلّق:** لا يجوز تنفيذه قبل استكمال المعلومات أو الاختبار.
- **مرفوض/ملغى:** لا يُعاد العمل به دون قرار جديد موثق.

كل قرار جديد يضيف: التاريخ، الحالة، القرار، الجهة، السبب، الأثر، وطريقة التراجع عند الحاجة. لا تحذف القرارات القديمة؛ أضف قرارًا لاحقًا يوضح أنها استُبدلت.

## ADR-001 — GitHub هو سجل المشروع الدائم

- التاريخ: 2026-11-02
- الحالة: **معتمد تشغيليًا — توصية هندسية**
- القرار: حفظ ميثاق المشروع والقرارات والحالة وخطوات استعادة السياق داخل `docs/` في المستودع.
- السبب: محادثات ChatGPT قد لا تظهر على جهاز آخر بسبب حساب مختلف أو إعدادات/مشكلة مزامنة أو استخدام محادثة مؤقتة؛ كما أن سياق المحادثة لا ينبغي أن يكون المصدر الوحيد للقرارات.
- الأثر: يمكن فتح الملفات نفسها من GitHub على أي جهاز، ويمكن بدء محادثة جديدة مع رابط المستودع وملف الحالة.
- القيد: يجب ألا يحتوي المستودع العام على أسرار أو بيانات شخصية.

## ADR-002 — إبقاء المشروع مجانيًا وعدم اشتراط الدفع

- التاريخ: 2026-11-02 (تفضيل مستمر سبق أن ذكره المستخدم)
- الحالة: **معتمد — تفضيل المستخدم**
- القرار: الأولوية لاستضافة وأدوات مجانية لا تطلب بطاقة، وعدم إنشاء موارد مدفوعة أو تفعيل الدفع الإلكتروني.
- السبب: الميزانية صفر ولا توجد بطاقة أو وسيلة دفع متاحة.
- الأثر: نختار الخدمات بعد التحقق من شروطها الحالية، وقد نحتاج إلى تقليل مكونات التشغيل أو استخدام بديل أبسط إذا كانت الخطة المجانية لا توفر موارد كافية.
- حد القرار: لا نقدم وعودًا بأن منصة كاملة عالية الموارد ستعمل مجانًا إلى الأبد.

## ADR-003 — إبقاء مستودع GitHub عامًا مع حماية الأسرار

- التاريخ: 2026-11-02 (بناءً على طلب المستخدم السابق)
- الحالة: **معتمد — تفضيل المستخدم**
- القرار: الإبقاء على `HVA09/lumen-learning-platform` عامًا.
- السبب: تجنب التكاليف والحفاظ على وصول سهل من عدة أجهزة.
- ضوابط إلزامية: عدم رفع ملفات البيئة الحقيقية أو الرموز أو مفاتيح التشفير أو كلمات المرور أو بيانات المستخدمين. فحص الأسرار لا يعوض عن تدوير أي سر حقيقي سبق كشفه.

## ADR-004 — الدفع معطل في النسخة المجانية

- التاريخ: 2026-11-02
- الحالة: **معتمد تشغيليًا — توصية هندسية متوافقة مع تفضيل المستخدم**
- القرار: `PAYMENT_PROVIDER=disabled` افتراضيًا، ولا يتم استدعاء checkout/cancellation كمسار دفع فعّال عند التعطيل.
- السبب: عدم وجود وسيلة دفع لدى المستخدم، وتجنب ربط إطلاق المنصة ببوابات مالية.
- الأثر: لا تفعّل Stripe أو PayPal ولا تضف أسرارها حتى يصدر طلب صريح وتتوفر المتطلبات.

## ADR-005 — العمل عبر فرع تطوير وPull Request بدل الكتابة المباشرة إلى main

- التاريخ: 2026-11-02
- الحالة: **معتمد تشغيليًا — توصية هندسية**
- القرار: تجميع العمل الحالي في PR #4 على فرع `fix/security-production-hardening`، وترك `main` محميًا.
- السبب: تقليل احتمال إفساد الفرع الافتراضي وإتاحة فحص التغييرات قبل اعتمادها.
- الأثر الحالي: PR #4 مفتوح وغير مدمج. آخر main المعروف هو `da33265617b61baaccdea05de5015f73bd1b5d56`. آخر head موثق عند إنشاء هذا السجل هو `89891d1d520555beed5a3e6013c05d6ae14ae7a9`.
- ملاحظة: لا يُفترض أن كل ما على فرع PR أصبح موجودًا في main.

## ADR-006 — الاختبارات وفحوصات الأمن لا تُتجاوز

- التاريخ: 2026-11-02
- الحالة: **معتمد تشغيليًا — توصية هندسية**
- القرار: لا دمج ولا نشر قبل نجاح الفحوصات على أحدث commit بالضبط، بما فيها backend وfrontend/build وفحص الأسرار.
- السبب: كثرة الإضافات دون اختبارات موثوقة ترفع احتمال إدخال أعطال أو تسريب بيانات.
- الأثر: طلب المستخدم تجاوز المراجعة البشرية الاختيارية لا يساوي السماح بتعطيل CI أو تجاوز حماية GitHub.

## ADR-007 — فحص الأسرار التاريخية مع استثناءات ضيقة فقط

- التاريخ: 2026-11-02
- الحالة: **معتمد تشغيليًا — توصية هندسية**
- القرار: تنفيذ فحص Gitleaks لنطاق التغييرات والتاريخ الكامل، وعدم استثناء مجلد الاختبارات أو قاعدة الكشف كاملة. تُستثنى بصمات محددة بعد مراجعة أنها قيم اختبار وهمية.
- السبب: المستودع عام، وقد تظهر أسرار قديمة في تاريخ Git أو أرشيفات مضمنة.
- الأثر: استثناء fingerprint لا يثبت وحده أن القيمة آمنة؛ يجب إعادة فحص أي نتيجة جديدة. إذا ظهر سر حقيقي، يوقف النشر ويُلغى/يُدوّر السر لدى مزوده.

## ADR-008 — عدم ادعاء جاهزية الإنتاج قبل اختبار البيئة الحقيقية

- التاريخ: 2026-11-02
- الحالة: **معتمد تشغيليًا — توصية هندسية**
- القرار: فصل نجاح الاختبارات الآلية عن جاهزية الاستضافة والنشر.
- السبب: SMTP وHTTPS وClamAV وLTI والنسخ الاحتياطي الخارجي ومفاتيح الإنتاج تحتاج إعدادًا واختبارات على البيئة المستهدفة.
- الأثر: لا نقول "تم النشر" أو "جاهز للإنتاج" قبل وجود دليل تشغيل فعلي.

## ADR-009 — لا تعتمد استعادة المشروع على ذاكرة المحادثة

- التاريخ: 2026-11-02
- الحالة: **معتمد — طلب المستخدم وتوصية هندسية**
- القرار: في نهاية كل مرحلة تطوير، حدّث `PROJECT_STATUS.md` و`DECISIONS.md` عند تغير القرارات، وسجّل commit وPR ونتائج CI والمهام القادمة.
- السبب: المستخدم يتنقل بين جهازين وقد يبدأ محادثة جديدة.
- الأثر: يمكن متابعة العمل من ملف الحالة حتى عند فقدان المحادثة؛ لا يمكن لهذا الإجراء وحده إصلاح مزامنة سجل ChatGPT، لكنه يمنع فقدان سجل المشروع.
