# LUM-010 — قرارات خصوصية التحليلات ولوحة المتصدرين

**التاريخ:** 2026-11-18  
**الحالة:** قرار منتج معتمد؛ التنفيذ البرمجي لم يكتمل  
**النطاق:** خصوصية تحليلات أداء الطلاب ولوحة المتصدرين في Lumen

هذا السجل يكمل سياسة ملكية محتوى المنهج المعتمدة في سياسة B. وهو مستقل عنها: السماح للمعلمين بقراءة المنهج المشترك لا يعني السماح لهم برؤية بيانات أداء جميع الطلاب.

## 1. لوحة المتصدرين العامة

### القرار
لا تُعرض أسماء الطلاب أو درجاتهم الفردية في لوحة متصدرين عامة على مستوى المنصة لجميع المعلمين أو المستخدمين.

### قواعد الوصول
- الطالب: يرى تقدمه ونتائجه الشخصية.
- المعلم: يرى لوحة المتصدرين الخاصة بالفصول التي يدرّسها فقط، وبحسب عضوية الفصل وصلاحياته.
- المعلم غير المرتبط بالفصل: لا يرى أسماء طلاب ذلك الفصل أو درجاتهم.
- المدير (Admin): يمكنه الاطلاع على بيانات المؤسسة لأغراض إدارية مشروعة، وفق صلاحيات الإدارة وسجلات التدقيق.
- أي إحصاء عام خارج النطاق الصفي يجب أن يكون مجمعاً ومجهول الهوية، وألا يسمح بإعادة تحديد هوية الطالب من مجموعات صغيرة.

### متطلبات التنفيذ
- إيقاف/إزالة خيار «كل المنصة» الذي يكشف display_name وscore وrank على مستوى المنصة، أو استبداله بعرض مجمع مجهول الهوية.
- الإبقاء على لوحة الفصل مع تحقق server-side من عضوية الفصل وصلاحية المعلم أو المدير.
- اختبارات API تثبت منع المعلم غير المرتبط بالفصل من رؤية أسماء الطلاب أو درجاتهم.
- اختبارات DTO تثبت عدم تسريب البريد أو معرفات الحسابات أو حقول تعريفية غير لازمة.
- لا تعتمد على إخفاء عناصر الواجهة؛ يجب فرض السياسة في API.

## 2. تحليلات أداء الأسئلة

### القرار
التحليلات التفصيلية تقتصر على المعلم المسؤول عن الفصل الذي تنتمي إليه بيانات الأداء، وعلى المدير وفق صلاحياته. لا يحق لكل المعلمين الاطلاع على نتائج جميع الطلاب لمجرد امتلاكهم دور teacher.

### قواعد الوصول
- المعلم: يرى تحليلات طلاب فصوله فقط.
- المعلم غير المسؤول عن الفصل: لا يرى نتائج طلاب ذلك الفصل.
- المدير: يمكنه رؤية تحليلات المؤسسة لأغراض إدارية مشروعة.
- أي لوحة عامة أو مشتركة خارج نطاق الفصل يجب أن تستخدم بيانات مجمعة ومجهولة الهوية، دون إمكانية إعادة تحديد الطالب.

### قيد تقني معروف
التدقيق السابق لاحظ أن `GET /content/topics/{topic_id}/analytics` يجمع نتائج الأسئلة عبر الطلاب، وأن نموذج `QuizAttempt` الحالي لا يوفر علاقة موثوقة ومباشرة بالفصل الدراسي تسمح بتقييد التحليلات حسب المعلم.

لذلك لا يجوز تنفيذ فلترة شكلية أو تخمين الفصل من بيانات غير موثوقة. يلزم أولاً تصميم مصدر موثوق لنطاق الأداء، مثل ربط المحاولة بالفصل/التكليف عند إنشائها والتحقق من عضوية الطالب والمعلم وقت الوصول، مع معالجة المحاولات التاريخية التي لا تملك هذا السياق.

### متطلبات التنفيذ
- تصميم نموذج نطاق موثوق يربط بيانات الأداء بالفصل/التكليف دون إعادة إسناد تاريخي تخميني.
- تحديد سياسة للمحاولات القديمة التي لا تحتوي على سياق فصل موثوق: لا تُعرض كبيانات فردية للمعلمين؛ تبقى ضمن صلاحيات الإدارة أو ضمن تجميع مجهول الهوية بعد تقييم مخاطر إعادة التعرف.
- تطبيق فحص server-side على analytics endpoint وكل مسار بديل أو export يعرض البيانات نفسها.
- اختبارات cross-teacher وcross-class وadmin، واختبارات بيانات تاريخية بلا سياق.
- عدم تنفيذ migration أو تغيير إنتاجي قبل مراجعة التصميم وخطة الترحيل والرجوع.

## 3. مبادئ مشتركة

1. الصلاحية تُفرض في backend/API، وليس في الواجهة فقط.
2. أقل قدر من البيانات اللازمة لكل دور (data minimization).
3. عدم كشف بيانات الطالب الفردية خارج العلاقة التعليمية المصرح بها.
4. البيانات المجمعة ليست مجهولة تلقائياً؛ يجب تقييم حجم المجموعة وإمكانية إعادة التعرف.
5. لا إعادة تعيين ملكية أو فصل أو سياق تاريخي بالتخمين.
6. الاحتفاظ بسجلات تدقيق لعمليات الاطلاع الإداري على البيانات الحساسة.
7. الاختبارات الآلية لا تعادل قبولاً يدوياً أو مراجعة خصوصية شاملة.

## 4. علاقة القرار بسياسة ملكية المحتوى

تبقى سياسة B كما هي:
- القراءة المشتركة للدروس والأسئلة متاحة للمعلمين.
- التعديل والحذف للمنشئ أو admin.
- المحتوى المزروع/القديم الذي لا يملك منشئاً موثقاً يديره admin فقط.

هذه السياسة لا تمنح صلاحية الوصول إلى تحليلات الطلاب أو لوحة المتصدرين العامة.

## 5. الحالة وخطوات العمل

- **قرار المنتج:** معتمد في 2026-11-18.
- **تنفيذ سياسة B لملكية المحتوى:** دُمج عبر PR #169.
- **تنفيذ خصوصية لوحة المتصدرين:** لم ينفذ بعد؛ يحتاج PR مستقل واختبارات.
- **تنفيذ خصوصية التحليلات:** لم ينفذ بعد؛ يحتاج تصميم نطاق بيانات موثوق قبل migration أو تعديل API.
- **البيانات التاريخية:** لا تعديل أو حذف أو backfill تخميني.
- **الإنتاج:** لا تغيير إنتاجي ولا تشغيل migration ضمن هذا السجل.

لا يُغلق LUM-010 حتى يكتمل تنفيذ القرارات، وتنجح اختبارات الوصول، وتتم مراجعة جميع المسارات البديلة التي تعرض هذه البيانات.
