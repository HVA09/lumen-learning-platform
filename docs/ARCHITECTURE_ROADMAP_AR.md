# خارطة الطريق الهندسية والمعمارية لمنصة Lumen

> **الإصدار:** تحديث خط الأساس بتاريخ 2026-10-31  
> **مرجع الكود:** سلسلة الفروع حتى PR #14، commit \`da70a4f6f0e4d8c1af61593e8de81874e2b5300f\`.  
> **تنبيه:** حالة الفروع ونتائج CI لا تعني أن هذه التغييرات أصبحت جزءاً من \`main\` أو أنها منشورة بالإنتاج.

## 1. الرؤية والهدف

بناء منصة تعليمية احترافية ذات بنية منظمة وقابلة للصيانة والقراءة والتطوير والتوسع، وآمنة ومستقرة. المعيار ليس مجرد إضافة ميزات تعمل، بل بناء نظام يمكن اختباره ومراجعته وتشغيله وتحسينه على المدى الطويل.

## 2. القرارات المعمارية المعتمدة

1. اعتماد **Modular Monolith** حالياً: وحدات مجال واضحة داخل تطبيق واحد. لا ننتقل إلى Microservices قبل وجود حاجة تشغيلية مثبتة.
2. فصل المسؤوليات بين API ومنطق الأعمال والوصول إلى البيانات والتكاملات والبنية التحتية.
3. تقليل الترابط بين الوحدات وتحديد عقود واضحة للتواصل بينها.
4. إعادة التنظيم تدريجياً، دون إعادة كتابة دفعة واحدة أو كسر الوظائف الحالية.
5. كل تغيير مهم يجب أن يصاحبه اختبار وتوثيق مناسب.
6. لا دمج إلى \`main\` ولا نشر إنتاجي دون موافقة صريحة من مالك المشروع.
7. وفق توجيه مالك المشروع يمكن تجاوز انتظار المراجعة البشرية لبعض التغييرات، لكن لا يجوز تجاوز CI أو بوابات الأمان والتشغيل.
8. نجاح CI لا يثبت وحده جاهزية الإنتاج؛ تكاملات الطرف الثالث وTLS واستعادة النسخ يجب اختبارها في بيئة مناسبة.

## 4. ما تحقق في الأمن والتشغيل على سلسلة الفروع

### الهوية والجلسات والفوترة
- أسرار TOTP تُخزن مشفرة باستخدام Fernet، مع مفتاح ثابت يجب حفظه في Secret Manager خارج المستودع.
- أحداث Stripe وPayPal الموثقة لها سجل idempotency لمنع تطبيق الحدث المكرر.
- جلسات المتصفح تستخدم Cookies من نوع HttpOnly، مع CSRF وجلسات منفصلة للأجهزة وتدوير refresh token وإبطال إعادة الاستخدام.

### رفع الملفات
- تحقق من نوع الملف وتوقيعه وبنية بعض الحاويات قبل الفحص.
- ClamAV يستقبل الملف عبر INSTREAM على دفعات، ولا يُنشر منفذه TCP 3310 على المضيف.
- تعطل الفاحص يؤدي إلى رفض الرفع (fail closed) في الإنتاج.
- توجد حصص افتراضية لكل مستخدم: 100 MiB و100 ملف، إضافة إلى الحد الأقصى لكل ملف.
- PR #12 يعالج فحص الحصة المبكر والتزامن وتنظيف الملف عند الفشل أو إلغاء الطلب.
- صورة ClamAV مثبتة على فرع LTS؛ يجب توفير موارد كافية، مع مراعاة تقدير 3 GiB كحد أدنى و4 GiB مفضلة وفق توثيق ClamAV.

### الاعتماديات والنسخ الاحتياطي
- الواجهة تستخدم \`frontend/package-lock.json\`، وCI يثبت Node.js 22.23.4 ويستخدم \`npm ci\`.
- PR #14 يبني نسخة PostgreSQL في ملفات مؤقتة، ويتحقق من gzip قبل نشر الاسم النهائي، ولا يحذف النسخ القديمة إلا بعد نشر نسخة سليمة.
- سكربت الاستعادة يتحقق من أرشيف gzip قبل إرسال SQL ويشترط \`--confirm\`.
- CI اختبر حالات فشل pg_dump والضغط والأرشيف التالف وغياب تأكيد الاستعادة. هذا لا يغني عن تمرين استعادة فعلي على قاعدة بيانات غير إنتاجية.

## 5. البنية الحالية مقابل البنية المستهدفة

### Backend الحالي

البنية الحالية ما زالت أفقية في معظمها:
- \`app/auth/\`
- \`app/routers/\`
- \`app/models/\`
- \`app/schemas/\`
- \`app/services/\`
- \`app/content/\`

هذا يوفر فصلاً أولياً بين المسارات والنماذج والمخططات والخدمات، لكنه لا يضع كل مكونات المجال الواحد في وحدة واحدة بعد. كما أن \`main.py\` يسجل المسارات مركزياً.

### Backend المستهدف

\`\`\`
backend/app/
  core/              الإعدادات والأمن والسجلات والاستثناءات
  api/v1/             تجميع واجهات API وإصداراتها
  modules/
    identity/
    learning/
    assessments/
    progress/
    review/
    classes/
    assignments/
    files/
    billing/
    notifications/
    administration/
    integrations/lti/
  infrastructure/
    database/
    cache/
    queue/
    storage/
    observability/
  main.py
\`\`\`

هذا تصميم مستهدف فقط؛ لا توجد دعوة لإنشاء مجلدات فارغة أو نقل الملفات دفعة واحدة. ننقل وحدة حقيقية عند وجود اختبارات وخطة تراجع، وننشئ Repository عند وجود حاجة فعلية فقط.

### Frontend الحالي والمستهدف

الواجهة الحالية React/Vite، وملفات الميزات ما زالت مجمعة إلى حد كبير تحت \`src/components/\`، مع عملاء API في \`src/lib/\` وملف تجميع رئيسي \`src/App.jsx\`.

الشكل المستهدف:

\`\`\`
frontend/src/
  app/                 routes, layouts, providers
  features/
    auth/
    learning/
    assessments/
    classes/
    assignments/
    files/
    billing/
    notifications/
    dashboard/
  shared/
    components/
    hooks/
    api/
    utilities/
  i18n/
  styles/
\`\`\`

لا ننقل مكونات ميزة إلى shared لمجرد أنها قابلة للاستيراد. كل Feature تمتلك مكوناتها وخدمات API واختباراتها، والعناصر العامة فقط توضع في shared.

## 6. بوابات الإنتاج المتبقية

| البوابة | الوضع الحالي | ما يلزم للإغلاق |
|---|---|---|
| دمج سلسلة الكود | لم تُدمج | مراجعة تسلسل PRs، اعتماد الدمج وفق موافقة المالك، ثم تحقق CI على نقطة الدمج |
| HTTPS | غير مفعّل في Nginx الافتراضي؛ كتلة 443 والتحويل ما زالت معلّقة | نطاق حقيقي، شهادة صالحة، تفعيل TLS واختبارها من الخارج |
| Moodle/Canvas LTI | لم يُجر اختبار إطلاق حقيقي | حساب sandbox، تسجيل الأداة والمنصة، اختبار login/launch وتطابق claims وعمليات exchange |
| Grade Passback | غير منفذ | تصميم واختبار AGS إذا كان مطلوباً |
| الاستعادة | اختبارات سكربتات CI ناجحة | تجربة restore كاملة على PostgreSQL منفصل، والتحقق من عدد الجداول والبيانات والعلاقات |
| إعداد الإدارة الأول | توجد آلية CLI محلية | تنفيذها مرة في البيئة المستهدفة بواسطة مالك موثوق وبسر آمن |
| إدارة الأسرار | الكود يطلب أسراراً إنتاجية | إعداد JWT وTOTP وDB ومفاتيح مزودي الدفع في Secret Manager دون وضعها في Git |
| ClamAV على الاستضافة | تكامل Docker مهيأ | تحقق من الذاكرة والتواقيع والمهل واستقرار الفحص على موارد الاستضافة الفعلية |
| الأداء | يوجد تحذير سابق عن حجم حزمة الواجهة | تحليل bundle وتقسيم الشيفرة وقياس تحميل أولي حقيقي |
| اختبار المتصفح | CI يغطي Vitest وBuild | E2E للعمليات الأساسية على بيئة staging متصلة بالخلفية وقاعدة البيانات |

لا تُغلق بوابات HTTPS أو LTI افتراضياً أو باستخدام نطاقات/حسابات تخمينية؛ تحتاج موارد حقيقية يملكها المشروع.

## 8. قواعد العمل

- فرع مستقل لكل مجال واضح، وعدم تغيير main مباشرة.
- لا دمج لأي PR قبل اجتياز CI.
- لا نشر إنتاجي دون موافقة مالك المشروع وعبور بوابات البيئة الحقيقية.
- لا حذف وظائف أو نقل واسع دون اختبارات تثبت الحفاظ على السلوك.
- لا أسرار أو كلمات مرور أو مفاتيح فعلية في المستودع أو السجلات.
- بعد كل خطوة: مراجعة Diff، نتائج CI، وتحديث الوثائق.

**القرار المعتمد:** Modular Monolith، إعادة هيكلة تدريجية، أمن متعدد الطبقات، اختبارات لكل تغيير، وتوثيق مستمر، مع حماية الوظائف الحالية وعدم اعتبار فرع التطوير نسخة الإنتاج.
